# Эксплуатация

## Резервное копирование

Вся информация системы — в одной базе PostgreSQL. Копия делается скриптом:

```bash
DATABASE_URL=postgres://… ./scripts/backup.sh /var/backups/yappibot
```

Скрипт создаёт архив `yappibot-ГГГГММДД-ЧЧММСС.dump`, проверяет, что он читается, и удаляет копии старше 14 дней (`KEEP_DAYS`). Ежедневный запуск в 03:30 через cron:

```
30 3 * * * cd /opt/yappibot && set -a && . ./.env && set +a && ./scripts/backup.sh /var/backups/yappibot >> /var/log/yappibot-backup.log 2>&1
```

В варианте с Docker:

```bash
docker compose exec -T db pg_dump -U yappibot --format=custom yappibot > backups/yappibot-$(date +%Y%m%d).dump
```

Копии на том же сервере не спасут при потере сервера — выгружайте их во внешнее хранилище (S3-совместимое, другой сервер).

## Восстановление

Скрипт восстанавливает только в **пустую** базу и откажется работать, если в базе уже есть таблицы — так нельзя случайно затереть рабочие данные.

```bash
sudo systemctl stop yappibot
createdb yappibot_restored
DATABASE_URL=postgres://…/yappibot_restored ./scripts/restore.sh /var/backups/yappibot/yappibot-….dump
# укажите новую базу в DATABASE_URL в .env
npm run db:migrate          # догонит схему, если копия старее кода
sudo systemctl start yappibot
```

Раз в несколько месяцев проверяйте копию: восстановите её в отдельную базу и сравните число клиентов и заказов. Скрипты проверены на локальной базе: данные и счётчик номеров заказов после восстановления совпадают.

## Обновление

```bash
./scripts/backup.sh /var/backups/yappibot   # копия перед обновлением
git pull
npm ci
npm run build
npm run db:migrate
sudo systemctl restart yappibot
```

Перезапуск после сборки обязателен: сервер запоминает список файлов веб-клиента при старте. Данные при перезапуске сохраняются, неотправленные уведомления дошлются из очереди.

## Миграции схемы

1. Измените `apps/server/src/db/schema.ts`.
2. `npm run db:generate` — в `apps/server/drizzle/` появится SQL-файл. Прочитайте его.
3. `npm run db:migrate`, затем `npm test`.

Применённые миграции не редактируются — исправления вносятся новой миграцией.

## Логи и наблюдение

Сервер пишет структурированные JSON-логи в stdout: `journalctl -u yappibot -f` или `docker compose logs -f app`. Данные входа и cookie из логов вырезаются.

| Что смотреть               | Как                                                                                                        |
| -------------------------- | ---------------------------------------------------------------------------------------------------------- |
| Сервер жив                 | `GET /api/health` — подключите внешний монитор доступности                                                 |
| Неотправленные уведомления | `SELECT notification_type, last_error, count(*) FROM notifications WHERE status = 'FAILED' GROUP BY 1, 2;` |
| Очередь уведомлений        | `SELECT count(*) FROM notifications WHERE status = 'PENDING';` — должно быть около нуля                    |
| Действия сотрудников       | Админ-панель → «Аудит»                                                                                     |

## Частые ситуации

| Симптом                                    | Причина и решение                                                                                                   |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------- |
| Приложение пишет «Откройте через Telegram» | Открыто по прямой ссылке в браузере — это ожидаемо. Клиенты входят через бота                                       |
| У всех клиентов ошибка входа (401)         | `BOT_TOKEN` в `.env` не от того бота, из которого открывают приложение, либо часы сервера сильно спешат или отстают |
| Сотрудник видит «Нет доступа»              | Его Telegram ID не добавлен в «Сотрудники» или доступ отозван                                                       |
| В админке нет кнопки входа через Telegram  | Не задан `BOT_USERNAME` или у бота не выполнен `/setdomain`                                                         |
| Бот не отвечает на `/start`                | Не выполнен `npm run bot:setup`, либо `TELEGRAM_WEBHOOK_SECRET` изменили и не запустили команду заново              |
| Команда не получает уведомления            | Бот не добавлен в рабочий чат либо неверный ID чата; при личных уведомлениях сотрудник не нажал `/start`            |
| Клиент не получает уведомления             | Клиент заблокировал бота — запись `FAILED` с ошибкой 403. Заказы и бонусы при этом не страдают                      |
| «Рулетка временно недоступна»              | Сумма вероятностей активных призов не равна 100% либо активных призов меньше двух                                   |
| Потерян доступ владельца                   | `npm run owner:create -- --telegram-id … --name …`                                                                  |
| Скидка по бонусу равна нулю                | Заказ меньше минимальной суммы приза или услуга не входит в допустимые — причина указана в карточке заказа          |
