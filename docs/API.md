# HTTP API

Базовый адрес — адрес приложения (`APP_URL`). Формат — JSON. Типы ответов описаны в `apps/server/src/contract/api.ts`.

- Даты — строки ISO 8601 (UTC). Денежные суммы — десятичные строки: `"8500.00"`.
- Ошибка: `{ "error": { "code": "BONUS_RESERVED", "message": "понятный текст на русском" } }`.
- Коды: `400` некорректные данные, `401` нет подтверждённого входа, `403` нет прав, `404` не найдено (в том числе чужая запись), `409` действие невозможно в текущем состоянии, `429` слишком часто.

## Авторизация

| Кто                  | Как                                                                           |
| -------------------- | ----------------------------------------------------------------------------- |
| Клиент               | Заголовок `Authorization: tma <initData>` — строка `Telegram.WebApp.initData` |
| Сотрудник в Telegram | Тот же заголовок                                                              |
| Сотрудник в браузере | Cookie `yappi_admin`, выдаётся `POST /api/admin/auth/widget`                  |

## Клиент

| Метод | Путь                               | Описание                                                                                                                    |
| ----- | ---------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| GET   | `/api/home`                        | Профиль, активный бонус, доступность рулетки, последний заказ, настройки                                                    |
| GET   | `/api/roulette`                    | Сегменты колеса (без вероятностей) и доступность вращения                                                                   |
| POST  | `/api/roulette/spin`               | Вращение. Тело: `{ "requestId": "<uuid>" }`. Лимит 10/мин                                                                   |
| GET   | `/api/bonuses`, `/api/bonuses/:id` | Бонусы клиента                                                                                                              |
| POST  | `/api/bonuses/:id/apply`           | «Применить бонус»: бонус ждёт активации, сотрудники с правом `bonuses.redeem` получают уведомление с кнопками. Идемпотентно |
| PUT   | `/api/me/locale`                   | Сменить язык: `{ locale }`, где locale — `ru`, `en` или `uk`. Меняет интерфейс, сообщения бота и кнопку меню                |
| GET   | `/api/orders`, `/api/orders/:id`   | Заказы клиента                                                                                                              |
| POST  | `/api/orders`                      | Создать заявку. Лимит 10/мин                                                                                                |
| GET   | `/api/activity`                    | Лента активности                                                                                                            |

**Идемпотентность.** `requestId` во вращении и в заявке — UUID, который клиент создаёт один раз на действие. Повтор запроса с тем же `requestId` возвращает уже созданный результат (`replayed: true` у вращения, код `200` вместо `201` у заявки) и не создаёт второй приз или заявку.

Создание заявки:

```json
{
  "requestId": "0b6f…",
  "serviceType": "Логотип",
  "description": "Что нужно сделать",
  "wishes": "необязательно",
  "referenceUrl": "https://… — необязательно",
  "desiredDeadline": "необязательно",
  "contact": "необязательно",
  "useBonus": true
}
```

Клиент не передаёт ни свой идентификатор, ни идентификатор бонуса: при `useBonus: true` сервер сам берёт единственный активный бонус клиента.

Причины недоступности рулетки (`availability.reason`): `ACTIVE_BONUS`, `NO_ATTEMPTS`, `COOLDOWN`, `NOT_CONFIGURED`, `BLOCKED`.

## Кнопки в боте

Под уведомлением о применённом бонусе две кнопки: `ba:<id бонуса>` — активировать, `br:<id бонуса>` — вернуть клиенту. После активации под сообщением остаётся кнопка `sg:<id бонуса>` — начислить этому клиенту вращение. Нажатия приходят на webhook как `callback_query` и выполняют те же операции, что и маршруты админки, с теми же проверками прав.

## Админ-панель

Все маршруты — под `/api/admin`. В скобках — необходимое право.

### Вход и профиль

| Метод | Путь           | Описание                                            |
| ----- | -------------- | --------------------------------------------------- |
| POST  | `/auth/widget` | Вход по данным Telegram Login Widget; ставит cookie |
| POST  | `/auth/logout` | Выход                                               |
| GET   | `/me`          | Сотрудник, его права, настройки                     |

### Показатели

| Метод | Путь                                            | Описание                                                               |
| ----- | ----------------------------------------------- | ---------------------------------------------------------------------- |
| GET   | `/dashboard?from&to`                            | Дашборд. Финансы — только с `finance.view`                             |
| GET   | `/stats?from&to`                                | Статистика (`stats.view`)                                              |
| GET   | `/export/{clients\|orders\|bonuses\|spins}.csv` | Выгрузка CSV (`reports.export`); принимает те же фильтры, что и списки |

`from`, `to` — даты `ГГГГ-ММ-ДД` включительно; по умолчанию последние 30 дней.

### Клиенты

| Метод | Путь                                       | Описание                                                                                                             |
| ----- | ------------------------------------------ | -------------------------------------------------------------------------------------------------------------------- |
| GET   | `/clients?q&status&hasBonus&sort&dir&page` | Список (`clients.view`)                                                                                              |
| GET   | `/clients/:id`                             | Карточка: заказы, бонусы, оплаты, активность, действия сотрудников                                                   |
| POST  | `/clients/:id/status`                      | Блокировка: `{ status, reason }` (`clients.manage`)                                                                  |
| GET   | `/spins/lookup?q=…`                        | Найти клиента по @username или Telegram ID и узнать, можно ли начислить ему вращение (`spins.grant`)                 |
| POST  | `/spins/grant`                             | Начислить одно вращение: `{ userId }` (`spins.grant`). Отказ, если у клиента уже есть вращение или действующий бонус |

### Заказы

| Метод | Путь                                                           | Описание                                                                         |
| ----- | -------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| GET   | `/orders?q&status&paymentStatus&staffId&hasBonus&from&to&page` | Список (`orders.view`)                                                           |
| GET   | `/orders/:id`                                                  | Карточка с историей статусов, оплатами и журналом                                |
| POST  | `/orders`                                                      | Заявка от имени клиента: поля заявки + `userId` (`orders.create`)                |
| POST  | `/orders/:id/status`                                           | `{ status, reason? }` (`orders.update_status`)                                   |
| POST  | `/orders/:id/price`                                            | `{ subtotal }` — пересчитывает скидку и итог (`orders.set_price`)                |
| POST  | `/orders/:id/assign`                                           | `{ staffId \| null }` (`orders.assign`)                                          |
| POST  | `/orders/:id/confirm-payment`                                  | `{ amount, paymentReference?, notes? }` (`payments.confirm`)                     |
| POST  | `/orders/:id/redeem-bonus`                                     | Подтвердить использование бонуса (`bonuses.redeem`)                              |
| POST  | `/orders/:id/cancel`                                           | `{ reason, refunded? }` (`orders.cancel`; `refunded` требует `payments.confirm`) |
| POST  | `/orders/:id/release-bonus`                                    | Вернуть резерв клиенту: `{ reason }` (`bonuses.release`)                         |
| POST  | `/orders/:id/attach-bonus`                                     | Привязать активный бонус клиента к неоплаченному заказу (`bonuses.release`)      |

Действия возвращают обновлённую карточку заказа. `confirm-payment`, `redeem-bonus` и `cancel` идемпотентны: повторный вызов возвращает текущее состояние и ничего не меняет.

### Бонусы и рулетка

| Метод | Путь                                         | Описание                                                                                                                                                         |
| ----- | -------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET   | `/bonuses?q&status&type&userId&from&to&page` | Список (`bonuses.view`). `q` ищет по номеру бонуса в любом написании (`YB-7KQ4MX`, `yb 7kq4mx`, `7kq4mx`), имени клиента, username, Telegram ID и названию приза |
| GET   | `/bonuses/:id`                               | Карточка с историей                                                                                                                                              |
| POST  | `/bonuses/:id/activate`                      | Активировать бонус — списать его (`bonuses.redeem`). Идемпотентно                                                                                                |
| POST  | `/bonuses/:id/return`                        | Вернуть клиенту бонус, ожидающий активации: `{ reason? }` (`bonuses.release`)                                                                                    |
| POST  | `/bonuses/grant`                             | Ручная выдача: `{ userId, prizeId, reason }` (`bonuses.grant`)                                                                                                   |
| POST  | `/bonuses/:id/cancel`                        | Аннулировать активный: `{ reason }` (`bonuses.cancel`)                                                                                                           |
| POST  | `/bonuses/:id/correct`                       | Вернуть в активные: `{ reason, extendDays? }` (`bonuses.correct`)                                                                                                |
| GET   | `/prizes`                                    | Призы (`roulette.manage` или `bonuses.grant`)                                                                                                                    |
| PUT   | `/prizes`                                    | Сохранить конфигурацию целиком: `{ prizes: [...] }` (`roulette.manage`)                                                                                          |

`PUT /prizes` отклоняет конфигурацию, если активных призов меньше двух или сумма их вероятностей не равна ровно 100%. Призы, которых нет в списке, архивируются.

### Рассылки

Все маршруты требуют право `broadcast.send`.

| Метод | Путь                              | Описание                                                                                                                                                  |
| ----- | --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET   | `/broadcasts`                     | История рассылок с прогрессом и размер аудитории по языкам                                                                                                |
| POST  | `/broadcasts/media?kind=…&name=…` | Загрузка вложения, `kind` — `photo` или `voice`. Тело запроса — сам файл (`application/octet-stream`). Возвращает `{ mediaKind, mediaFileId }`            |
| POST  | `/broadcasts/test`                | Отправить сообщение только себе                                                                                                                           |
| POST  | `/broadcasts`                     | Запустить рассылку: `{ text, mediaKind, mediaFileId, buttons: [{ text, url }], locale }`; `url: null` — кнопка открытия приложения, `locale: null` — всем |
| POST  | `/broadcasts/:id/cancel`          | Остановить идущую рассылку                                                                                                                                |
